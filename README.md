# صدى (Sada)

تطبيق غرف صوتية وفيديو ومكالمات فورية، مبني على **Metered Video SDK**.
يغطي الشاشات الثماني في التصميم: الترحيب، الرئيسية (فقاعات الغرف)، غرفة جديدة، غرفة صوتية، غرفة فيديو، ومكالمة مباشرة.

```
sada/
├─ server/   Express: يخفي المفتاح السري، ينشئ الغرف ويصدر التوكنات ويتتبع الحضور
└─ client/   React + Vite، واجهة عربية RTL، يحمّل Metered SDK من CDN
```

## التشغيل المحلي

1. أنشئ حساباً على https://dashboard.metered.ca (التطبيق يُنشأ تلقائياً).
2. من لوحة Metered خذ:
   - **اسم التطبيق** من الصفحة الرئيسية (مثال `myapp`، فيصبح النطاق `myapp.metered.live`).
   - **Secret Key** من *Developers* (يظهر بعد الضغط على Reveal).
3. نفّذ:
   ```bash
   cp server/.env.example server/.env     # ثم الصق القيمتين
   npm run install:all
   npm run dev                            # الخادم :8787 والواجهة :5173
   ```
4. افتح http://localhost:5173 في **نافذتين** (إحداهما خاصة) بأسماء مختلفة لتجربة الغرف والمكالمات.

> المتصفح لا يسمح بالميكروفون والكاميرا إلا عبر HTTPS أو localhost.
> لتجربة الجوال على نفس الشبكة استخدم نفقاً مثل `cloudflared tunnel --url http://localhost:5173` أو ngrok.

## النشر (خدمة واحدة)

```bash
npm run install:all && npm run build
METERED_APP_NAME=... METERED_SECRET_KEY=... npm start   # يخدم الواجهة والـAPI معاً
```
يصلح على Render أو Railway أو Fly.io. اضبط المتغيرين من لوحة المنصة، وتأكد أن النطاق HTTPS.

## كيف يعمل مع Metered

| الوظيفة | الآلية |
|---|---|
| إنشاء غرفة | `POST /api/v1/room` من الخادم، الغرف **private** دائماً وتنتهي تلقائياً بعد ٦ ساعات |
| الدخول | الخادم يصدر توكناً عبر `POST /api/v1/token`، والمضيف يأخذ `isAdmin: true` |
| الصوت والفيديو | `Metered.Meeting()` ← `join` / `startAudio` / `startVideo` / `startScreenShare` |
| المتحدث النشط | حدث `activeSpeaker` |
| رفع اليد، المنصة، التفاعلات، النص المباشر | رسائل JSON عبر دردشة Metered (`sendChatMessage`) بعلامة `__sada` |
| قائمة الغرف والأصدقاء المتاحون | نبضة حضور كل ٤ ثوانٍ إلى `/api/presence` (في ذاكرة الخادم) |
| مكالمة مباشرة | غرفة خاصة لشخصين `dm-xxxx`، والطرف الآخر يتلقى الدعوة عبر نبضة الحضور |

## ما لم يُنفَّذ أو يحتاج قراراً منك

- **لم يُجرَّب على حساب Metered حقيقي.** كتبتُ الشيفرة على وثائق Metered الحالية، لكن لم أستطع تشغيلها هنا. أول اختبار فعلي سيكشف أي اختلاف بسيط في الحقول.
- **لا حسابات ولا قائمة أصدقاء.** الهوية اسم محفوظ في الجهاز، و«الأصدقاء المتاحون» هم كل من يفتح التطبيق الآن. خيار «أصدقائي» في الغرفة يُخزَّن لكن لا يُفرض بعد. أضف تسجيل دخول (Firebase Auth أو Supabase) ثم اربط `externalUserId` بالمستخدم.
- **منصة المتحدثين تُفرض من الواجهة فقط.** المضيف يحدد من يتحدث، لكن عميلاً معدَّلاً يستطيع نشر صوته. للتشديد الحقيقي استخدم غرفتين (واحدة للمتحدثين) أو `ownerOnlyBroadcast`.
- **جمهور كبير (مئات أو آلاف):** جميع المستمعين يستقبلون صوت المتحدثين مباشرة. للأعداد الكبيرة فعّل `enableLiveStreaming` (HLS) على الغرفة ليستمع الجمهور عبر بث بدلاً من الاتصال المباشر.
- **النص المباشر** يستخدم Web Speech API في المتصفح (يعمل جيداً في Chrome)، وهو **نص وليس ترجمة**. الترجمة الفورية تحتاج خدمة ترجمة تضيفها عند `sendCaption`.
- **الحالة في الذاكرة:** إعادة تشغيل الخادم تنسى الغرف وقائمة الحضور. انقلها إلى Redis عند تعدد النسخ.
- **حذفتُ عمداً** زر التأثيرات ✨ من المكالمة (لا فلاتر حقيقية خلفه)، وخيار «لدي حساب بالفعل»، وشارة التسجيل في غرفة الفيديو (التسجيل غير مفعّل). تبديل الجدولة معروض لكنه معطّل وموسوم «قريباً».
- **شاشة «الرادار»** (الفقاعات المتناثرة حول أفاتار المستخدم) لم تُبنَ؛ الرئيسية مبنية على التصميم الآخر ذي الفقاعات والفلاتر.
- أفاتارات هندسية بلون ثابت لكل اسم. استبدل `components/Avatar.jsx` بصور المستخدمين أو بالرسومات الموجودة في التصميم.

## الأمان

- `METERED_SECRET_KEY` لا يغادر الخادم أبداً ولا يُطبع في السجلات.
- أضف تحديد معدل الطلبات (مثل `express-rate-limit`) قبل النشر العام.
